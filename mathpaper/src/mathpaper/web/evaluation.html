What reaches the top five?

LOCAL CPU · INT8 · N = 50 · K = 5

The same ten questions search all three papers. The score asks a simple question: did the search reach a page marked as useful for this question?

WHAT IS AN EVIDENCE-PAGE HIT?

Finding the right page.

For each test question, we first marked the PDF pages containing useful supporting material. The search returns five passages—short excerpts from the papers. The question gets one hit if at least one excerpt comes from a marked page in the correct paper.

Reading 9/10: for nine of the ten test questions, the search reached a reference page among its first five results. The shorthand “@5” means we check only those first five passages.

ILLUSTRATIVE EXAMPLE

Suppose the useful pages in one paper are 5 and 6. The search returns these five excerpts from that paper:

p. 2p. 6 ✓p. 9p. 3p. 2

That is one hit: an excerpt came from page 6. Finding several excerpts from the reference pages still counts as one hit for that question.

This measures whether search reached a reference page. The excerpt and generated answer still need checking for relevance, correctness, and complete assumptions.

WHAT THIS TAUGHT US

The keyword baseline holds up.

BM25 and hybrid + reranking each hit 9/10 questions in this set. These results give no basis to claim that reranking improves overall retrieval quality.

The reranked search misses the Gaussian separation definition. That makes statement lookup a useful tool to investigate, with broader evaluation still needed.

02 / CANDIDATE BUDGET

Less work. The same observed page hits.

SEPARATE LOCAL RUN · ONE CPU THREAD
—lower median local query time

Reducing the reranking pool from 50 to 20 candidates kept the result at 9/10 page hits on the same development questions. The agent now uses 20 candidates per search.

A deployment tradeoff observed on this set. INT8 inference, batch size 1, one ONNX Runtime thread, five retained passages. Render timings differ.

Current configuration

Passages
Page-contained, label-aware; 220-token budget, 24-token overlap when splitting
Embedding
all-MiniLM-L6-v2 · 384 dimensions
Fusion & reranking
BM25 + cosine search · RRF 60 · ms-marco-MiniLM-L6-v2 cross-encoder
Agent search
20 candidates · 5 passages · INT8 ONNX
Research tools
Passage search, statement lookup, and context expansion through MCP
Answer checks
Retrieved source IDs only, followed by a separate model support check; the checker can make mistakes

What to measure next

  1. Unseen questions. Build a separate test set with theorem comparisons, proof dependencies, and unanswerable questions.
  2. Complete evidence. Label relevant passages and check whether all required assumptions are available.
  3. Answer support. Review mathematical correctness and citation entailment independently of the generating model.
  4. Further ablations. Compare chunk sizes, retained passage counts, and agent tools on the separate set.

Current statistics support a development comparison. They do not estimate held-out answer accuracy, hallucination rates, or production latency percentiles.
